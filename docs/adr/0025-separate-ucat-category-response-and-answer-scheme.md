# Separate UCAT category, response type, and answer scheme

UCAT content uses three independent concepts: Question stem category describes the assessed item type and remains the unit used for set composition, Response type describes the candidate interaction, and Answer scheme defines answer state, validation, persistence, scoring, and review. Runtime behavior is owned by one shared deep response-contract module with a fixed registry of supported schemes; categories provide authoring defaults only, and neither category-name conditionals nor an author-configurable response rules engine may define behavior. Situational Judgement Most/Least Appropriate remains a distinct category so tutors and set-building rules can count it independently, even though its drag-and-drop behavior belongs to its Answer scheme. The migration uses an expand, activate, contract rollout: compatibility exists only long enough to backfill and verify every row and attempt snapshot, after which `question_type`, `is_answer`, the `syllogism` enum value, `syllogism_v1` readers, and category-driven behavior are removed from the active model rather than retained indefinitely.
