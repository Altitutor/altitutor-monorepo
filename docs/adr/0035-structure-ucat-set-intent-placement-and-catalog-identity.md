# Structure UCAT set intent, placement, and catalog identity

UCAT question sets store authoring intent rather than a free display name and unexplained duration. A set records its section, full- or partial-section format, required immutable blueprint reference, and one timing intent: exam-relative pace, fixed answering duration, or untimed. Pace is working speed (`0.7×` is slower and allows more time), and a standalone paced attempt resolves answering seconds from the referenced blueprint's per-question allowance, actual question count, and pace when the attempt starts. Mock component sets instead use their selected mock blueprint's exact section timing. Attempt records capture the resolved deadline and expanded catalog name so later catalog or blueprint changes do not rewrite history.

Catalog identity is a derived projection of structured placement and mutable contiguous positions; it is not stored as another synchronized name field or maintained by rename triggers. Database views/functions and the shared application formatter expose the same expanded and compact forms. The former free `name` becomes an optional tutor-only authoring note. Standalone sets have independent global sequences per section and format and render as, for example, `Verbal Reasoning Full Set 1` by default or `VR Full Set 1` in constrained space. Mocks have one global sequence independent of test year and render as `Mock 1`; their attached sets use contextual names such as `Mock 1 Verbal Reasoning` or compact `Mock 1 VR`. Blueprint test year remains provenance rather than catalog identity, so an unchanged set or mock does not become nominally obsolete each year.

A set is either standalone or belongs to at most one mock, represented by a nullable direct mock reference rather than a many-to-many membership table. Creating a mock requires an explicit immutable blueprint version and atomically creates its four fixed-order section slots and component sets. Attachment is a draft composition operation: it verifies ownership and section-slot compatibility, then rebases the set to the mock blueprint with full-section `1×` intent. The completed component must satisfy the slot's question, category, stem, and timing rules before the mock can be published. Draft mocks may explicitly detach a component set; detachment preserves the set and its reference, appends it to the relevant standalone sequence, and leaves an empty slot that blocks publication until filled. Soft-deleting a mock does not detach its component sets.

Tutor ordering is an explicit catalog operation, not a side effect of filtering or ordinary table sorting. Standalone sets reorder only inside their section-and-format sequence; mocks reorder only inside the global mock sequence. Insertions, deletions, attachments, detachments, and format changes keep affected positions contiguous. Section order within a mock is fixed by its blueprint. Production cuts over to these invariants by auditing and mapping existing content to database-managed blueprint versions before constraints are made mandatory; incompatible content is archived or rebuilt rather than supported through legacy null-blueprint or hardcoded-format paths.
