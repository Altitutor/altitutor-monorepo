# Structure UCAT set intent, placement, and catalog identity

UCAT question sets store authoring intent rather than a free display name and unexplained duration. A set records its section, full- or partial-section format, required immutable blueprint reference, and one timing intent: exam-relative pace, fixed answering duration, or untimed. Pace is working speed (`0.7×` is slower and allows more time), and a standalone paced attempt resolves answering seconds from the referenced blueprint's per-question allowance, actual question count, and pace when the attempt starts. Mock component sets instead use their selected mock blueprint's exact section timing. Attempt records capture the resolved deadline and expanded catalog name so later catalog or blueprint changes do not rewrite history.

Catalog identity is a derived projection of structured placement and mutable contiguous positions; it is not stored as another synchronized name field or maintained by rename triggers. Database views/functions and the shared application formatter expose the same expanded and compact forms. The former free `name` becomes an optional tutor-only authoring note. Published sets in the sets pool have independent global sequences per section and format and render as, for example, `Verbal Reasoning Full Set 1` by default or `VR Full Set 1` in constrained space. Draft and in-review sets remain visible to tutors but are unnumbered and do not reserve a position; they append to their sequence when they enter the sets pool as published. Published mocks have one global sequence independent of test year and render as `Mock 1`; draft and in-review mocks remain visible to tutors but are unnumbered and do not reserve a position. A published non-deleted mock occupies its attached sets, which then use contextual names such as `Mock 1 Verbal Reasoning` or compact `Mock 1 VR`. Deleted and unpublished mocks keep ownership for restoration but do not occupy those sets, so published public components keep standalone catalog identity until the mock occupies them again or they are explicitly detached. Blueprint test year remains provenance rather than catalog identity, so an unchanged set or mock does not become nominally obsolete each year.

A set is either standalone or belongs to at most one mock, represented by a nullable direct mock reference rather than a many-to-many membership table. Creating a mock requires an explicit immutable blueprint version but creates no component sets. Its four fixed-order blueprint section slots are a composition requirement rather than placeholder records: tutors fill them later by attaching an eligible existing set or creating a set in that slot. Attachment is a draft composition operation: it verifies ownership and section-slot compatibility, then rebases the set to the mock blueprint with full-section `1×` intent. Every slot must contain a completed component whose official question total and answering time match the selected blueprint before the mock can be published; category ranges and questions-per-stem remain visible warnings. Sending a mock for review submits remaining draft component sets first, and publishing a mock publishes unpublished component sets first; if any child transition fails, the mock status does not change. Draft mocks may explicitly detach a component set; detachment preserves the set and its reference as a standalone set and leaves the slot unfilled. Soft-deleting a mock does not erase or detach its component-set ownership links, so restoration remains lossless; however, that deleted parent is inactive for catalog membership and its surviving published public sets remain eligible for the sets library with standalone catalog identity. Draft and in-review mocks likewise do not reserve their published public component sets from the sets library, while still appearing in the tutor mocks column. Only a non-deleted published mock excludes its sets from the standalone pool and supplies mock-relative names. Soft-deleted sets are absent from stem membership projections and do not reserve their stems from the practice-question pool. Mock publication and published-mock write guards require official question totals and answering times; category ranges and questions-per-stem remain visible warnings.

Automatic set filling is additive for existing sets. Existing stem membership and order are preserved, those questions count toward the selected total and category targets, and the builder chooses only the remaining whole stems on a best-effort basis using the same blueprint, visibility, category, range, and unused-stem criteria as new-set creation. The tutor reviews the combined preview and saves the set explicitly.

Tutor ordering is an explicit catalog operation, not a side effect of filtering or ordinary table sorting. Published standalone sets reorder only inside their section-and-format sequence; unpublished sets appear after that sequence for tutor visibility but cannot be reordered and consume no position. Published mocks reorder only inside the global mock sequence; unpublished mocks appear after that sequence for tutor visibility but cannot be reordered and consume no position. Publication, withdrawal, deletion, attachment, detachment, and format changes keep affected published positions contiguous. Section order within a mock is fixed by its blueprint. Production cuts over to these invariants by auditing and mapping existing content to database-managed blueprint versions before constraints are made mandatory; incompatible content is archived or rebuilt rather than supported through legacy null-blueprint or hardcoded-format paths.
