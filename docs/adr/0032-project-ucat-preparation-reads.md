# Project UCAT preparation reads and move maintenance off GET

UCAT Progress reads use a per-Student, per-question best-attempt projection that admits exam-style evidence only when its parent activity completes and admits standalone or Learn submissions immediately. Score projection GET serves only a persisted daily snapshot; its fixed 120-day trajectory is derived from observed recent practice and is independent of Study-plan enablement, scheduled workload, target score, and test date. Score evidence is projected per completed activity and the model reads at most the 200 newest activities per section.

Completed activity durably coalesces one refresh request, refreshes Score projection, and reconciles equivalent Study-plan work after the response. Learn and Skill-trainer completion routes kick the same durable worker immediately. Failed jobs use exponential backoff, dead-letter after five attempts, and revive when genuinely new activity arrives.

Ordinary Progress, Score projection, and Study-plan GET requests do not refresh evidence, reconcile tasks, generate guidance, or regenerate a plan. Due weekly/missed-work maintenance and completed Mocks run the canonical planner in the background; ordinary Sets only refresh Score and reconcile equivalent tasks. A service-role RPC assembles the authenticated Student view inputs in one bounded bundle, while immutable catalogue inputs are shared for 60 seconds across a worker burst. Set and Mock reuse reads one projected latest-completion fact per asset, capped at the 512 most recent of each type, rather than lifetime attempt histories. The scheduled worker therefore uses the same Preparation policy, test-date boundary, readiness evidence, and inventory selection as explicit generation without restoring page-read fan-out. Canonical generation marks missed historical tasks skipped before replacing future work, preserving history without rolling backlog forward.
