# Tutor-web UCAT question-generation prompt audit

## Conclusion

No. The active tutor-web generator does **not** give the model the attached prompt verbatim. It implements much of the same intent through several layers, but the effective request is:

1. a database-backed base system prompt plus writer prompt;
2. a generated JSON user brief containing section rules, enabled section/category/tag prompt layers, a server-built plan, selected source examples, output requirements, and the expected shape; and
3. optional source-example images as multimodal user content.

The attachment is therefore a useful specification of the desired workflow, not a description of the exact current model payload.

This audit compares [`pasted-text.txt`](/Users/matthewchua/.codex/attachments/eabac17c-fe43-4dfa-8626-96b416c3f12a/pasted-text.txt) with the repository source as at 28 July 2026. It does not query the deployed database, so an administrator-edited live prompt or prompt layer could differ from the migration baseline.

## What the model actually receives

The UI submits section, optional category, model profile, source mode, optional selected source IDs, stem count, difficulty, time burden, target tag IDs, image mode, and up to 2,000 characters of run instructions ([modal](../../apps/tutor-web/src/features/ucat/questions/components/generated/GenerateQuestionStemsModal.tsx#L538-L565), [request schema](../../apps/tutor-web/src/features/ucat/questions/server/generate-question-stems.ts#L55-L68)). The authenticated API queues the request and prepares reference/example context before background execution ([route](../../apps/tutor-web/src/app/api/ucat/question-stems/generated/generate/route.ts#L9-L27), [queue setup](../../apps/tutor-web/src/features/ucat/questions/server/start-question-generation.ts#L48-L91)).

The writer system message is exactly the current database row's `base_system_prompt`, two newlines, then `writer_prompt` ([generation call](../../apps/tutor-web/src/features/ucat/questions/server/generate-question-stems.ts#L1380-L1394)). Those values are read at runtime from `ucat_ai_generation_system_prompts` ([config resolution](../../apps/tutor-web/src/features/ucat/shared/server/ucat-ai-client.ts#L313-L357)). The migration baseline is a short UCAT-ANZ/style/anti-copy system prompt and a near-publishable writer prompt ([base prompt seed](../../supabase/migrations/20260622120000_decouple_ucat_ai_models_and_prompts.sql#L80-L120)); the latest writer migration asks for compact, self-contained content, natural structured data presentation, one defensible key, plausible error-based distractors, and decisive explanations ([writer update](../../supabase/migrations/20260710120000_relax_qr_writer_presentation_prompt.sql#L4-L20)).

The user message is produced by `buildWriterPrompt`. It contains the brief, local plan, section rules, enabled prompt layers, compact source examples, optional presentation/Venn references, a rich-content contract, extensive section/category-specific requirements, and an illustrative output shape ([writer prompt](../../apps/tutor-web/src/features/ucat/questions/lib/ai-generation/prompts.ts#L269-L417)). If selected examples contain images, signed images and anti-copy instructions are appended as user content ([image content](../../apps/tutor-web/src/features/ucat/questions/server/generate-question-stems.ts#L385-L415)).

There are no authoring tools in this model call. A chat-completions provider receives `response_format: {type: "json_object"}` and system/user messages, not a function-tool list or provider-enforced JSON Schema ([AI client](../../apps/tutor-web/src/features/ucat/shared/server/ucat-ai-client.ts#L500-L530)). The response is parsed/repaired as JSON and then checked with Zod locally ([JSON handling](../../apps/tutor-web/src/features/ucat/shared/server/ucat-ai-client.ts#L556-L602), [candidate schema](../../apps/tutor-web/src/features/ucat/questions/lib/ai-generation/schema.ts#L187-L237)). Visuals are requested as structured content blocks; deterministic or AI image rendering happens server-side after a candidate passes gates ([content contract](../../apps/tutor-web/src/features/ucat/questions/lib/ai-generation/prompts.ts#L232-L266), [image resolution](../../apps/tutor-web/src/features/ucat/questions/server/generate-question-stems.ts#L1640-L1662)).

One potentially confusing detail: `AI_GENERATION_SYSTEM_PROMPT`, `buildPlanningPrompt`, `buildCriticPrompt`, and `buildRewriterPrompt` exist in `prompts.ts`, but the active executor imports only `buildWriterPrompt` ([imports](../../apps/tutor-web/src/features/ucat/questions/server/generate-question-stems.ts#L15-L21)). The richer hard-coded system constant is therefore **not** the active system message, and the current generation run does not make separate planner, critic, or rewriter model calls.

## Validation and retry reality

The post-response path is useful but narrower than the attachment implies:

- Zod enforces parseable content/visual structures and normalises explanation shape ([schema](../../apps/tutor-web/src/features/ucat/questions/lib/ai-generation/schema.ts#L165-L237)).
- Deterministic gates enforce answer count, explanation presence, section/category shapes, visual constraints, and textual near-copy detection ([gate entry point](../../apps/tutor-web/src/features/ucat/questions/lib/ai-generation/gates.ts#L901-L923)).
- A failed call, schema mismatch, or blocking gate gets at most one fresh same-category regeneration: two attempts total ([attempt constant](../../apps/tutor-web/src/features/ucat/questions/server/generate-question-stems.ts#L78-L81), [loop](../../apps/tutor-web/src/features/ucat/questions/server/generate-question-stems.ts#L1375-L1383), [blocking retry](../../apps/tutor-web/src/features/ucat/questions/server/generate-question-stems.ts#L1551-L1583)). The retry note says the previous attempt failed, but does not pass the actual issue list back to the model ([retry note](../../apps/tutor-web/src/features/ucat/questions/server/generate-question-stems.ts#L461-L485)).
- The unused critic/rewriter prompt builders do not provide independent solving in this active generation call. A separate blind-solver/moderator assessment is queued only after generated stems have been persisted for review ([post-persistence assessment](../../apps/tutor-web/src/features/ucat/questions/server/run-background-generation.ts#L76-L115)).

## Bottom line

The current generator is directionally close to the attachment on UCAT formats, explanations, calibration, anti-copying, structured visuals, and tutor-review workflow. The largest real gaps are:

1. the attachment is not the literal system prompt;
2. source examples are truncated and not quality-screened;
3. reference timing and server-side tag-to-section validation are missing;
4. the deterministic plan is less complete than the requested private plan;
5. multiple-choice option explanations and syllogism question-level strategy explanations are forcibly removed;
6. QR depth/calculator/full-precision requirements are weaker or absent;
7. logical/numerical correctness is not independently recomputed before acceptance; and
8. the current run uses writer + deterministic gates, not the repository's planner/critic/rewriter model stages.
