The big product distinction

MAILBOX STATE

“Someone read this.”

Read flags, folders and archive describe the email. They should stay consistent with Outlook.

Example: Jane opens a parent's message to understand it.

AGREED THREAD RESPONSIBILITY

“Someone owns the next reply.”

Assign one adminstaff and notify them. Reads preserve responsibility; incoming follow-ups retain and notify. Any staff reply clears it; later inbound remains unassigned.

Example: Jane is checking class availability; the message still needs an answer tomorrow.

DEV-151 reference check: its current spec clears assignment on read or reply. Matthew's latest email description keeps responsibility until reply. DEV-151 is owned by another agent and has only been read, not changed.

Two integration details change the scope

Same From address ≠ same Sent Items. Existing Resend emails do not automatically become Exchange mail. Mailbox-visible business notifications need an explicit delivery/reconciliation design.

Same parent address ≠ same Student context. A conversation can concern one child or several. Address matches can help discover context without proving which records own the request.

Ideas to borrow from Macro and Superhuman

Fast reading

Keyboard navigation, a focused reading pane, stable selection and list position.

Safe composition

Visible sending identity, saved drafts and clear recovery when a send outcome is uncertain.

Reusable language

Shared snippets and signatures, with context variables checked before sending.

Settled: separate thread responsibilityAssign one adminstaff to an email thread with an assignment notification. Keep read/unread shared with Outlook.
